My Project Walkthrough

Your own words for the question every interview opens with — "tell me about yourself" and "walk me through your current project." Rehearse this until it's natural, not memorized-sounding.

1. Self-introduction

Hello, my name is Kamlesh Kumar. I have 12 years of overall experience in software development, including 7 years of hands-on experience in React.js. Throughout my career, I have worked across multiple domains such as Banking, E-commerce, and E-learning, which has given me exposure to different business requirements and application architectures. Currently, I am working as an Associate Specialist at Synechron, where I am working for the U.S. Bank client.

2. Project overview — Regulatory Reporting Application

It is a regulatory reporting web application used by banks to report financial trades to regulators. The application supports multiple asset classes such as Foreign Exchange (FX), Interest Rates, Commodities, and Collateral.

Whenever a trade is executed, the bank is required to submit the trade details to the regulator. The regulator then validates the report and either accepts it, which is acknowledged as ACK, or rejects it, which is acknowledged as NACK. If a trade is rejected, the bank needs to identify the reason for the rejection, correct or modify the trade details, and replay the report.

Our application provides different dashboards and reports where users can monitor ACKs, NACKs, Data Mismatches, Trade Mismatches, and perform trade validation through a Reconciliation page.

Trade lifecycle, at a glance

StepWhat happens
1. Trade executedBank executes a trade in FX, Interest Rates, Commodities, or Collateral
2. Report submittedTrade details are reported to the regulator
3. Regulator validatesRegulator checks the report and responds
4a. ACKReport accepted — no further action needed
4b. NACKReport rejected — bank identifies the reason, corrects the trade, and replays the report
5. MonitoringUsers track ACKs, NACKs, data mismatches, and trade mismatches via dashboards and the Reconciliation page

3. Responsibilities

I have been involved in the complete frontend development lifecycle. My responsibilities include:

  • Developing new features using React.js
  • Integrating REST APIs with the frontend
  • Implementing searching, filtering, sorting, and pagination using AG Grid
  • Writing end-to-end automation test cases using Cypress
  • Collaborating closely with backend developers to finalize API contracts and resolve integration issues
  • Fixing production issues and providing quick support during releases
  • Deploying applications through the Shield Pipeline

4. Key challenge — AG Grid Server-Side Row Model

One of the most challenging tasks I worked on was implementing the AG Grid Server-Side Row Model. Initially, we faced several challenges because the frontend and backend needed to work together efficiently for server-side pagination, filtering, and sorting.

I spent time studying the AG Grid documentation in depth, created a detailed implementation document, and discussed the required backend API changes with the backend team. After the backend APIs were updated, I implemented the frontend changes, including server-side pagination, sorting, filtering, and data loading.

As a result, the feature worked successfully and significantly improved the application's performance by loading only the required data instead of the entire dataset.

5. Closing statement

Overall, I enjoy solving complex frontend problems, improving application performance, and building scalable React applications while collaborating effectively with cross-functional teams.

6. Delivery tips for the interview

Timing The full walkthrough above runs 2-3 minutes read aloud at a natural pace — about right for an opening "tell me about yourself." If asked specifically about a challenge (a very common follow-up), the AG Grid section alone is already shaped as a complete STAR answer — see the Agile & Leadership guide's STAR framework: Situation (frontend/backend needed to coordinate for server-side operations), Task (design and implement the Server-Side Row Model), Action (studied docs, wrote an implementation doc, aligned on API changes, built the frontend), Result (major performance improvement from loading only required data).
Where interviewers will probe deeper Be ready for follow-ups on: how AG Grid's Server-Side Row Model actually works under the hood (block-based lazy loading, the datasource interface) — cross-reference the Frontend System Design guide's data-grid worked example for the underlying virtualization/pagination mechanics; how you structured the REST API contract for server-side filtering/sorting — see REST APIs (pagination); and how you validated the feature — mention your Cypress E2E coverage, linking to Testing.
Keep it conversational This is written out in full so you can internalize the shape and the specific details (ACK/NACK, the four asset classes, Shield Pipeline) — but avoid reciting it verbatim in the room. Interviewers can tell, and a slightly looser, more natural retelling that hits the same beats lands better than a memorized script.
