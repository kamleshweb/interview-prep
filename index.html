Current project overview

The application is a regulatory reporting platform used by banks to report financial trades to regulators, supporting multiple asset classes — Foreign Exchange (FX), Interest Rates, Commodities, and Collateral.

Step What happens
1. Trade executed The bank is required to submit trade details to the regulator
2. Regulator validates Returns either an ACK (accepted) or a NACK (rejected)
3. If rejected (NACK) The bank identifies the rejection reason, corrects the trade details, and replays the report

The application provides dashboards and reports for monitoring ACKs, NACKs, Data Mismatches, and Trade Mismatches, plus a dedicated Reconciliation page for trade validation.

  • Writing end-to-end automation test cases using Cypress

  • Fixing production issues and providing quick support during releases
  • Deploying applications through the Shield Pipeline

Signature challenge — AG Grid Server-Side Row Model (STAR)

This is one of your strongest "tell me about a challenging technical problem" answers — it has a real architectural decision, cross-team coordination, and a measurable result. Structured using the STAR framework from the Agile & Leadership guide:

AG Grid Server-Side Row Model implementation
Situation

The application needed to display large trade datasets efficiently, but loading the entire dataset client-side didn't scale — the frontend and backend needed to work together for true server-side pagination, filtering, and sorting rather than client-side operations on an already-fetched dataset.

Task

Implement AG Grid's Server-Side Row Model so the grid requests only the data it actually needs per page/filter/sort state, instead of the whole dataset.

Action

Studied the AG Grid documentation in depth, created a detailed implementation document, and worked with the backend team to define the required API changes (the request/response contract for server-driven pagination, filtering, and sorting). Once the backend APIs were updated, implemented the frontend integration — server-side pagination, sorting, filtering, and data loading wired into AG Grid's server-side row model.

Result

The feature worked successfully and significantly improved application performance by loading only the required data instead of the entire dataset.
